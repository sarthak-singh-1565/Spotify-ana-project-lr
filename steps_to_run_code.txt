Complete Repository Setup and Execution Guide
For teaching assistants, evaluators, and project team members

This guide explains how to clone the GitHub repository, create an isolated Python virtual environment, install every required dependency, verify the installation, locate the dataset, run the project, and troubleshoot common setup errors.

1. Create requirements.txt
Place requirements.txt in the repository root. Add the third-party packages imported by the final project. For the libraries used in this project, a starting list is:

numpy
pandas
matplotlib
seaborn
scikit-learn

Important:
- The package is installed as scikit-learn but imported in Python as sklearn.
- Add any other third-party package that the final code imports.
- Do not list Python standard-library modules such as pathlib, os, math, csv, or datetime.
- For a reproducible submission, the team should test the project in a clean environment and then pin the exact tested versions. To record installed versions after a successful clean install, run:
  python -m pip freeze > requirements-lock.txt
  You may submit requirements-lock.txt as an additional lock file. If you choose to use it, document whether the TA should install requirements.txt or requirements-lock.txt. Do not create a lock file from an environment containing unrelated packages.

2. Create .gitignore
Create a plain-text file named .gitignore in the repository root. Suggested contents:

.venv/
venv/
env/
__pycache__/
*.py[cod]
.ipynb_checkpoints/
.vscode/
.idea/
.DS_Store
Thumbs.db

This prevents virtual environments, Python cache files, and common editor/OS files from being committed.

3. Check dataset availability and usage rights
- Confirm the CSV is actually present in the repository or provide a clear, permitted download procedure.
- Confirm the filename in the code exactly matches the committed filename.
- Do not commit private, restricted, or licensed data unless the project has permission to redistribute it.
- If the dataset is not committed, README.md must explain where the TA can obtain it and exactly where to place it.

4. Use a portable dataset path
Avoid paths tied to one team member's computer, such as:
  pd.read_csv("D:/College_Academics/spotify_churn_dataset.csv")

For a Python script, use a path based on the script location:

  from pathlib import Path
  import pandas as pd

  BASE_DIR = Path(__file__).resolve().parent
  DATASET_PATH = BASE_DIR / "spotify_churn_dataset.csv"
  df = pd.read_csv(DATASET_PATH)

This assumes the CSV is beside the Python file. If the CSV is in a data folder, use:
  DATASET_PATH = BASE_DIR / "data" / "spotify_churn_dataset.csv"

For Jupyter notebooks, __file__ is generally not defined. Use a path relative to the notebook's working directory or construct a path from the notebook location using an appropriate notebook workflow.

5. Check GitHub contents

- Confirm requirements.txt and .gitignore are visible on GitHub.

PART E — CREATE A VIRTUAL ENVIRONMENT
======================================================================

A virtual environment is an isolated Python installation for this project. It prevents packages installed for other projects from interfering with this project.

Run this command from the repository root:

  python -m venv .venv

If using the Windows Python launcher:
  py -3.11 -m venv .venv

If the command fails because the requested Python version is unavailable, install the version tested by the project team and repeat the command.

Do not copy a virtual environment from another computer. Create a new one on the TA's computer.

PowerShell execution-policy note:

Alternatively, follow your institution's IT guidance for PowerShell execution policy. Do not change system-wide security settings merely to activate this project.

PART I — DATASET AND FILE-PATH CHECKS
======================================================================

A FileNotFoundError usually means that the program cannot find the CSV at the path specified in the code.

Check:
- Is the dataset file present?
- Is the filename spelled exactly as in the code?
- Is the extension .csv?
- Is it in the repository root or the expected data folder?
- Does the code use an absolute path from a team member's computer?
- Is the terminal running from the expected folder?

Recommended script-based path:

  from pathlib import Path
  BASE_DIR = Path(__file__).resolve().parent
  DATASET_PATH = BASE_DIR / "spotify_churn_dataset.csv"

  if not DATASET_PATH.exists():
      raise FileNotFoundError(
          f"Dataset not found at: {DATASET_PATH}. "
          "Check that the CSV is in the project folder."
      )

  df = pd.read_csv(DATASET_PATH)

If the dataset is stored in a data folder:
  DATASET_PATH = BASE_DIR / "data" / "spotify_churn_dataset.csv"

Use the actual filename and folder structure in the repository.

PART J — COMMON ERRORS AND SOLUTIONS
======================================================================

1. ModuleNotFoundError: No module named 'numpy' (or pandas, seaborn, matplotlib, sklearn)
Cause: The dependency is not installed in the active environment, or the wrong interpreter is being used.
Solution:
  Activate .venv
  python -m pip install -r requirements.txt
  python -m pip check

For an individual missing package:
  python -m pip install numpy
  python -m pip install pandas
  python -m pip install matplotlib
  python -m pip install seaborn
  python -m pip install scikit-learn

2. 'python' is not recognized / command not found
Cause: Python is not installed or is not available on PATH.
Solution: Install Python, enable PATH integration on Windows where offered, reopen the terminal, and verify with python --version or py --version.

3. 'git' is not recognized / command not found
Cause: Git is not installed or its command-line tools are not on PATH.
Solution: Install Git, enable command-line integration, reopen the terminal, and verify git --version.

4. Could not open requirements.txt
Cause: The terminal is not in the repository root, or the file was not committed.
Solution:
  dir
  git status
Move into the folder containing requirements.txt or ask the project team to add and push the file.

5. FileNotFoundError for the CSV
Cause: Incorrect filename, folder, or hard-coded path.
Solution: Confirm the CSV is present and update the code to use a portable path based on the project directory.

6. PowerShell says scripts are disabled
Cause: PowerShell execution policy prevents the activation script from running.
Solution: Use Command Prompt activation:
  .venv\\Scripts\\activate.bat
Or follow institution-approved PowerShell policy guidance.

7. Packages install but imports still fail
Cause: Packages may have been installed into a different Python interpreter.
Solution:
  python -c "import sys; print(sys.executable)"
  python -m pip --version
The paths should refer to the same .venv environment.

8. Permission or network errors during installation
Cause: Restricted network, proxy, or insufficient permissions.
Solution: Check the internet connection and institutional proxy settings. Keep the virtual environment activated. Do not use administrator installation as the first workaround.

9. Incompatible Python/package version
Cause: The Python version may not be supported by one or more packages.
Solution: Use the Python version tested by the project team. Recreate the virtual environment with that interpreter and reinstall requirements.

10. Git reports authentication or repository access errors
Cause: The repository may be private or the TA may not have access.
Solution: The repository owner must grant access. Authenticate using GitHub's supported sign-in method. Never place passwords or personal tokens in project files.

PART K — CLEAN REINSTALL (ONLY IF THE ENVIRONMENT IS BROKEN)
======================================================================

If the environment is corrupted or contains conflicting packages, close running Python/Jupyter processes and recreate it.

First deactivate it:
  deactivate

Windows CMD:
  rmdir /s /q .venv
  python -m venv .venv
  .venv\\Scripts\\activate.bat

PowerShell:
  Remove-Item -Recurse -Force .venv
  python -m venv .venv
  .\\.venv\\Scripts\\Activate.ps1

macOS/Linux:
  rm -rf .venv
  python3 -m venv .venv
  source .venv/bin/activate

Then reinstall:
  python -m pip install --upgrade pip
  python -m pip install -r requirements.txt

Deleting .venv removes only the local environment, not the source code or dataset. Confirm the folder name before running a deletion command.
